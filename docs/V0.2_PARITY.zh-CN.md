# 博途 / 汇川 MCP 功能对照与实现记录

日期：2026-09-21。基准是本机 `inoproshop-mcp/src/server.ts` 与 `extended-tools.ts`（InoProShop MCP 1.1），不是按汇川产品宣传推测能力。

## 交付状态

本次将博途 MCP 从工程模式 6 个工具扩展到 27 个；inspect 为 16 个，online/control 为 30 个。工程预览接口还承载 10 种明确动作。工具数量不等于功能一一对应，也不表示全部实机验收完成。

已完成：本机 Siemens V21 Base/Step7 DLL 编译、离线输入校验、MCP stdio 注册/权限/结果返回、Worker 权限、超时/协议错序故障注入和重启恢复测试。

未完成：真实 TIA 工程对象操作验收、PLC 下载、在线读写变量/监视、独立 RUN/STOP、PLCSIM、全局库安装、语义符号重命名、Software Units、V20。尚不能称为“汇川全部功能已补齐”。需要 CPU 型号、真实 PLC 或 PLCSIM 版本，以及可用于验收的工程。

## 先研究后实现的结论

1. 汇川常驻 IronPython / CODESYS ScriptEngine 不能移植到博途。保留 .NET 10 MCP Host → 常驻 .NET Framework 4.8 Worker → V21 Openness。
2. 汇川 POU 对应博途 FB/FC/OB；ST 外部源在此为 SCL。DUT 主要对应 UDT，但不能把 CODESYS Union/Alias/Enum 无条件映射成 Siemens UDT。
3. GVL 不等于 PLC tag table：I/Q/M 符号走变量表，结构化全局存储走 GlobalDB。
4. 新建 FB/FC/OB/GlobalDB/UDT 使用外部源生成。LAD/FBD 等图形对象使用原生 XML 导出/导入，不能将 XML 当作 ST 程序。
5. CODESYS TaskConfiguration 对应关系是 Siemens OB 调度语义；通过 OB 属性和 XML 操作 CPU 支持的配置，不假定周期单位和优先级相同。
6. 工程修改使用 Openness 独占访问与事务。西门子明确禁止在事务内编译、保存和切换在线状态，所以通用修改先提交事务，之后由独立工具编译、保存。
7. V21 原生 CrossReferenceService 可提供真实交叉引用，因此 `find_references` 不用文本搜索冒充。
8. 官方“Running and stopping PLC”页面展示的是下载前/后的回调选择，不能据此实现一个暗中下载的独立启停工具。变量表/监控表的导出也不等于读取当前 PLC 运行值。

本机接口依据：`D:/Program Files/Siemens/Automation/Portal V21/PublicAPI/V21/net48/Siemens.Engineering.Base.xml`、`Siemens.Engineering.Step7.xml` 及对应 DLL。代码实际参与编译，避免仅凭网页或反射猜测方法签名。

## 通用工程动作示例

先 `get_project_structure`，复制返回的精确路径。中文/空格等名称使用 URL 编码的路径片段，不要自行拼接名称。旧 `browse_project_tree` 同步使用该编码方式。

创建 SCL 功能块：

```json
{
  "change": {
    "action": "create_source",
    "path": "PLC_1/Blocks",
    "name": "FB_Test",
    "format": "scl",
    "content": "FUNCTION_BLOCK \"FB_Test\"\nVAR_INPUT\n Enable : Bool;\nEND_VAR\nBEGIN\nEND_FUNCTION_BLOCK"
  },
  "projectPath": "D:/PLC/Test/Test.ap21"
}
```

把上面参数交给 `preview_engineering_change`，检查返回的 change、工程路径和警告，再把 `previewToken` 原样交给 `apply_engineering_change`。预览有效期 10 分钟、只使用一次、只能在原 Worker/工程会话中应用。应用后 `compile(plcName="PLC_1")`；检查结果后显式 `save_project`。

其他 change 示例：

```json
{"action":"create_source","path":"PLC_1/Types","name":"UDT_State","format":"udt","content":"TYPE \"UDT_State\"\nSTRUCT\n Ready : Bool;\nEND_STRUCT;\nEND_TYPE"}
{"action":"create_tag_table","path":"PLC_1/Tags","name":"Signals"}
{"action":"create_tag","path":"PLC_1/Tags/Signals","name":"Ready","dataType":"Bool","address":"%M0.0"}
{"action":"create_folder","path":"PLC_1/Blocks","name":"Motion"}
{"action":"move_object","path":"PLC_1/Blocks/FB_Test","destination":"PLC_1/Blocks/Motion"}
{"action":"rename_object","path":"PLC_1/Blocks/Motion/FB_Test","name":"FB_Axis"}
```

`import_xml` 的 path 是目标组，name 是 XML 中的真实对象名，content 是 `export_object` 得到并修改后的单对象 Siemens XML。它可以替换同一路径的已有对象；不接受跨对象的同名覆盖或块编号冲突。

`set_attribute` 应先读取目标对象，使用 API 暴露的实际属性名和值。I/O 地址/通道路径含 `@Addresses/<index>` / `@Channels/<index>`；不要猜参数单位或含义。

`add_device` 使用 `value=TypeIdentifier`、`name=站名称`、`destination=设备项名称`。TypeIdentifier 从硬件目录检索结果取得。

## 状态与失败语义

- 新通用修改：事务提交只表示工程对象变更成功；返回 `compiled=false`、`saved=false`。编译失败后不会自动撤销这种通用修改，须在 TIA 撤销对应 undo 单元或通过预览恢复原对象。
- 原块更新：独占访问内在 Worker 再查 SHA-256；导入使用事务，之后编译/导出，失败尝试恢复原源并核对哈希。保存失败单独返回 `save_failed`，明确内存中的改动可能仍在。
- 软件搜索不静默略过图形块/保护块；`complete=false` 时零命中不能证明不存在引用。分页读取不构成原子快照。
- 工程动作预览可能导出目标组的多个子对象以计算并发快照；保护对象无法导出时拒绝预览，而不是降低校验。
- 新建 CPU 或修改源码后，先显式编译成功再进行需要 XML 快照的预览。真实 V21 验证发现未编译对象会被 Siemens 以 inconsistent blocks 为由拒绝导出；不能在事务中编译来绕过此限制。
- 保存/创建/归档/打开失败不自动重试。归档操作的原生保存语义和未保存工程行为需实机验收。
- 默认等待 60 秒。可用 `TIA_AGENT_TIMEOUT_MS=1000..600000` 调整。超时不是取消，之后仅检查状态；只有 `completed` 允许 `recover_session(acknowledge=true)`。
- 未决状态位于 `%LOCALAPPDATA%/TiaAgentBridge/<安装目录哈希>/pending.json`；同安装目录由 `session.lock` 排他保护。`TIA_AGENT_STATE_DIRECTORY` 可指定专用状态目录。结果文件可能包含工程源码，按工程资料管理。
- 主进程异常退出且结果仍为 unknown 时不会自动解锁。需人工核对工程/Worker 状态；不要为绕过锁而重发同一写命令。
- 本次没有修改原始 zip、汇川代码、MCP 客户端配置或真实 PLC。
